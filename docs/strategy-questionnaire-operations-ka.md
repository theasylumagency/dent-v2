# სტრატეგიის კითხვარის მართვა

გვერდი: `/strategy`. ძირითადი ნაწილი შეიცავს ოთხ ბლოკსა და 13 კითხვას. დამატებითი კითხვები არასავალდებულოა. ბიუჯეტის, ანგარიშებზე მართვის წვდომისა და ერთთვიანი თანამშრომლობის შეფასების კითხვები ამოღებულია.

## გამოქვეყნება

კითხვარი არის არსებული Next.js/Payload პროექტის ნაწილი და ქვეყნდება იმავე განთავსებით. ამ სამუშაოს ფარგლებში მხოლოდ ლოკალური წინასწარი ნახვა შეიქმნა; მოქმედ დომენზე განთავსება ცალკე ნაბიჯია.

1. არსებულ წარმოების გარემოში ჩვეულებრივი სარეზერვო ასლის შემდეგ შესრულდეს `npm run migrate`. ახალი მიგრაციაა `20260919_085217_strategy_responses` და ამატებს მხოლოდ კითხვარის ცხრილსა და მის ინდექსებს.
2. შესრულდეს `npm run build` და განახლდეს საიტის პროცესი არსებული წესით.
3. შეიქმნას მოწვევა რეალური საკონტაქტო პირითა და შეთანხმებული შენახვის ვადით.
4. მოწვევის სრული ბმული გადაეცეს მხოლოდ შესაბამის ადამიანს. ბმულით სარგებლობა ნიშნავს იმავე ჩანაწერზე წვდომას; სხვადასხვა დამოუკიდებელი პასუხისთვის საჭიროა ცალკე მოწვევა.
5. გამოქვეყნებულ გარემოში შემოწმდეს შევსება, შენახვა და გაგრძელება მეორე მოწყობილობიდან.

პროექტის development ბაზას შეიძლება ჰქონდეს ავტომატურად განახლებული სქემა. თუ მიგრაციების ხელსაწყო მონაცემების დაკარგვაზე გაფრთხილებას აჩვენებს, არ დაადასტუროთ ბრმად და არ გაასუფთაოთ არსებული ბაზა. ახალი ცხრილის არსებობა და მიგრაციის ისტორია ცალკე უნდა შემოწმდეს.

## მოწვევა

მაგალითი — საკონტაქტო პირი შეცვალეთ რეალური ინფორმაციით:

```sh
npm run strategy -- invite --contact "საკონტაქტო პირის სახელი და არხი" --title "Total Charm Dent" --days 30 --retention 90
```

ნაგულისხმევი დომენია პროექტის `site.url`. ლოკალური შემოწმებისთვის დაამატეთ `--origin http://127.0.0.1:3000`.

პარამეტრები:

- `--contact`: სავალდებულო; ჩანს კითხვარის განმარტებაში, პასუხების წაშლის მოთხოვნისთვის.
- `--days`: მოწვევის მოქმედების ვადა დღეებში, 1–90; ნაგულისხმევად 30.
- `--retention`: პასუხების შენახვის დაგეგმილი ვადა, მინიმუმ მოწვევის ვადა და მაქსიმუმ 365 დღე; ნაგულისხმევად 90.
- `--title`: შიდა დასახელება, ადმინისტრატორისთვის.

ხელსაწყო აბრუნებს ჩანაწერის ნომერსა და სრულ ბმულს. ბმულის საიდუმლო ნაწილი მონაცემთა ბაზაში არ ინახება — ინახება მხოლოდ მისი ჰეში. დაკარგული ბმულის აღდგენა შეუძლებელია; ახალი მოწვევა ახალი კითხვარია. ხელახალი მოწვევისას წინა ჩანაწერი თვითნებურად არ წაშალოთ.

მოწვევის საიდუმლო ნაწილი არის `#access=...` ფრაგმენტში, ამიტომ საწყისი გვერდის მოთხოვნასთან სერვერის URL-ლოგში არ იგზავნება. გახსნისას გვერდი მას მისამართიდან შლის და API-ზე ცვლის HttpOnly სესიაზე. სესიას აქვს იგივე წვდომის შეზღუდვები, ვადა და გაუქმების წესი.

## პასუხების ნახვა და ექსპორტი

ადმინისტრატორი ხედავს კოლექციას **მარკეტინგი → სტრატეგიის კითხვარები**. რედაქტორის როლს და საჯარო მომხმარებელს კოლექციაზე წვდომა არ აქვს. ყველა ადმინისტრატორს აქვს ნახვის უფლება; მოწვევის რეალურ გამოყენებამდე გადაამოწმეთ, რომ ეს შეესაბამება პასუხებზე შეთანხმებულ წვდომას.

ფორმის პასუხები ადმინისტრაციაში წაკითხვადია და იქიდან არ რედაქტირდება. კითხვარი თავად ინახავს ცვლილებებს. ადამიანისათვის გასაგები ექსპორტი:

```sh
npm run strategy -- export --id 123 --output responses.json
```

ფაილი შეიცავს კითხვებისა და პასუხების ქართულ ტექსტს, სტატუსსა და თარიღებს. არსებული ფაილი არ გადაიწერება. ექსპორტი შეიძლება შეიცავდეს საკონტაქტო მონაცემებს — შეინახეთ სამუშაო დოკუმენტებთან და არა საჯარო საქაღალდეში. `--output`-ის გარეშე ექსპორტი იბეჭდება მიმდინარე ტერმინალში.

## მოწვევის გაუქმება და მონაცემების წაშლა

ადმინისტრაციის ჩანაწერში მონიშნეთ **წვდომის გაუქმება**, ან გამოიყენეთ:

```sh
npm run strategy -- revoke --id 123
```

ეს დაუყოვნებლივ ბლოკავს როგორც ბმულს, ისე უკვე გახსნილი სესიების შემდგომ წაკითხვა/ჩაწერას. უკვე ნანახ ან ჩამოტვირთულ ასლებს დისტანციურად არ შლის.

შენახვის ვადის გასვლის შემდეგ ჩანაწერი ფორმიდან მიუწვდომელია, თუმცა ფიზიკური წაშლა ცალკე სრულდება:

```sh
npm run strategy -- purge
```

ეს შლის მხოლოდ `deleteAfter`-ით ვადაგასულ კითხვარებს. ავტომატური ყოველდღიური გაშვება ამ ცვლილებაში არ არის დაყენებული. გამოქვეყნებამდე დანიშნეთ პასუხისმგებელი პირი ან ჩართეთ ეს ბრძანება სერვერის არსებულ დაგეგმილ სამუშაოებში. ვადამდე წაშლა შესაძლებელია ადმინისტრაციიდან; წაშლამდე შეთანხმებული ექსპორტი გააკეთეთ მხოლოდ საჭიროების შემთხვევაში. სარეზერვო ასლებსა და ჩამოტვირთულ ფაილებს საკუთარი შენახვის წესი სჭირდება.

## შენახვის ქცევა

- ცვლილებები სერვერზე ინახება მოკლე პაუზის შემდეგ და ნაბიჯის შეცვლისას.
- იმავე მოწვევის ბმული სხვა მოწყობილობაზე ხსნის იმავე შენახულ პასუხებს.
- მიმდინარე ჩანართში წარუმატებელი/მიმდინარე შენახვის სარეზერვო ასლი ინახება `sessionStorage`-ში, თუ ბრაუზერი ამის საშუალებას იძლევა. ის გადატვირთვას უძლებს, მაგრამ ჩანართის დახურვის შემდეგ მის შენარჩუნებას არ ვპირდებით.
- შენახვის შეცდომა ჩანს; შესაძლებელია ხელახალი ცდა და ადგილობრივი პასუხების ექსპორტი.
- თუ მეორე მოწყობილობამ უკვე შეცვალა ჩანაწერი, ძველი ვერსია სერვერის პასუხებს ვერ გადაწერს. მომხმარებელს შეუძლია ჩამოტვირთოს მიმდინარე ასლი და გახსნას სერვერზე შენახული ვერსია.
- გაგზავნა წარმატებულად ითვლება მხოლოდ სერვერის დასტურის შემდეგ. განმეორებითი გაგზავნა იმავე ჩანაწერს აბრუნებს და დუბლიკატს არ ქმნის.
- გაგზავნილი პასუხები იკეტება რედაქტირებისთვის.

## საჯარო საიტისგან განცალკევება

`/strategy` ცალკე განლაგებას იყენებს და არ ტვირთავს საიტის ანალიტიკის პროვაიდერს, სარეკლამო პიქსელებს ან საჯარო ნავიგაციას. გვერდს აქვს `noindex, nofollow`, პასუხების API-ს — `no-store`. გვერდი sitemap-ში არ ემატება.

ფორმის კითხვები საიდუმლო მონაცემი არ არის. პასუხების წაკითხვასა და ჩაწერას ყოველთვის სჭირდება მოქმედი მოწვევის სესია. მხოლოდ ჩანაწერის ნომრით პასუხების მიღება შეუძლებელია.

## შემოწმება

```sh
npm run test:strategy
npm run typecheck
```

ლოკალურ ბრაუზერში ასევე შემოწმებულია: მოწვევა, არჩევანის შეზღუდვა და რიგი, პირობითი ველები, განახლების შემდეგ აღდგენა, მეორე მოწყობილობა, კონფლიქტი, წარუმატებელი შენახვა/ხელახალი ცდა, საბოლოო გაგზავნა, გაუქმება, ვადის ამოწურვა და მობილურის სიგანე.

## დასრულების შემდეგ მოხსნა

ჯერ გადაიტანეთ საჭირო პასუხები შეთანხმებულ ადგილას და გააუქმეთ მოწვევები. შემდეგ შესაძლებელია `(strategy)` გვერდის, `api/strategy` მარშრუტის, strategy კომპონენტებისა და ბიბლიოთეკის, მართვის სკრიპტებისა და კოლექციის ამოღება; გაასუფთავეთ Payload-ის კონფიგურაცია, proxy-ის გამონაკლისი და გვერდის სათაურები. მონაცემთა ცხრილის წაშლა ცალკე, ახალი მიგრაციით შესრულდეს მხოლოდ მონაცემების შენახვის გადაწყვეტილების შემდეგ; ისტორიული მიგრაციები არ წაშალოთ.
